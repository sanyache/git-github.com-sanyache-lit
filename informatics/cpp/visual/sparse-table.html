Sparse table простою мовою

Як знайти максимум на будь-якому відрізку масиву миттєво, за O(1). І чому для цього зберігають саме відрізки довжиною 1, 2, 4, 8, 16…

Крок 1 · Задача

Багато запитів «який найбільший елемент від L до R?»

Маємо масив, який не змінюється. Нам ставлять дуже багато запитів: «знайди максимум серед елементів з номерами від L до R». Якщо щоразу проходити циклом, один запит коштує до n кроків. Для 100 000 елементів і 100 000 запитів це 10 мільярдів операцій. Задовго.

Хочеться один раз підготуватися (порахувати якусь таблицю), а потім відповідати на кожен запит за кілька дій.

Крок 2 · Перша ідея

Для сум є чудовий трюк: префіксні суми

Якщо треба було б шукати суму на відрізку, ми б порахували масив P, де P[i] — сума всіх елементів від початку до i. Тоді сума на відрізку [L, R] — це «сума до R» мінус «сума до L−1»:

сума[L..R] = P[R] − P[L−1]

Трюк працює, бо віднімання скасовує додавання. Ми знаємо, скільки «додав» зайвий початок, і просто забираємо це назад.

Крок 3 · Головна пастка

Чому з максимумом так не вийде

Спробуємо те саме: нехай PM[i] — максимум від початку до i. Для нашого масиву PM = [5, 5, 6, 6, 6, 8, 8, 8]. Тепер подивімося на два різні запити.

Ось і доказ. В обох запитах префіксний масив дає нам однакові числа: 6 і 6. А відповіді різні: 3 і 1. Отже, не існує жодної формули, яка з чисел 6 і 6 отримала б правильну відповідь в обох випадках. Віднімати, ділити, щось хитре робити марно: потрібної інформації в цих числах просто немає.

Куди зникла інформація? Число PM[i] пам'ятає лише переможця, а про всіх інших забуває. На малюнку переможець обох смужок той самий: шістка на позиції 2 (обведена червоним). Вона лежить саме в тій частині, яку ми хочемо відрізати. Коли ми її «викидаємо», дізнатися, хто був другим, уже неможливо.

Аналогія з забігом. Сума схожа на гроші в гаманці: знаєш, скільки було разом і скільки витратив, то знаєш, скільки лишилось. Максимум схожий на результат забігу: ти знаєш, хто переміг серед усіх бігунів, і хто переміг серед перших трьох. Якщо це та сама людина, ти нічого не знаєш про те, хто найшвидший серед решти.

Математично: для додавання є обернена дія (віднімання), а для максимуму оберненої дії немає. Тому «відрізати шматок» від максимуму не можна. Можна лише склеювати шматки.

Крок 4 · Рятівна властивість

Зате максимум не боїться перекриття

Раз відрізати не можна, будемо складати відповідь з готових шматків. І тут у максимуму є суперсила, якої немає у суми: якщо шматки перекриваються, нічого страшного. Елемент, порахований двічі, не стає більшим: max(x, x) = x.

Сума ✗12 + 16 = 28, а правильна сума 24. Клітинки 3 і 4 пораховано двічі, зайві 1 + 3 = 4.
Максимум ✓max(6, 8) = 8. Правильно! Повторно побачена одиниця чи трійка на відповідь не впливає.

Висновок: якщо ми заздалегідь знаємо максимуми деяких відрізків, то відповідь на запит — це максимум з двох таких відрізків, які разом накривають [L, R] і не виходять за його межі. Перекриватися вони можуть як завгодно.

Крок 5 · Що запам'ятати

Чому саме довжини 1, 2, 4, 8…

Можна було б запам'ятати максимуми всіх відрізків. Але для n = 100 000 це приблизно 5 мільярдів чисел. Не влізе в пам'ять. Потрібен невеликий набір відрізків, з якого будь-який запит складається з двох штук.

Sparse table зберігає для кожної позиції i відрізки довжиною 1, 2, 4, 8, … (степені двійки), що починаються в i. Подивимось, чому цього завжди вистачає.

Нехай довжина запиту len = R − L + 1. Візьмемо найбільший степінь двійки, який не перевищує len. Позначимо його 2k. Тоді:

2^k ≤ len < 2·2^k
  • Ліва нерівність (2k ≤ len) означає, що один блок не довший за запит. Отже блок, що починається в L, і блок, що закінчується в R, не вилазять за межі відрізка.
  • Права нерівність (len < 2·2k) означає, що два блоки разом довші за запит. Отже вони гарантовано накривають його повністю, без дірок посередині.

А чому не інші довжини? Ключ у тому, що сусідні збережені довжини відрізняються рівно вдвічі. Подивимось, що буде, якщо порушити правило.

Скільки це пам'яті? Різних степенів двійки до n всього близько log₂ n. Для 100 000 це 17. Тож таблиця має приблизно n · log₂ n ≈ 1,7 млн чисел замість 5 мільярдів. Звідси назва «розріджена» (sparse): зберігаємо не всі відрізки, а лише «рідкісні», але цього достатньо.

Є ще один бонус: блок довжиною 2k рівно ділиться на дві половинки довжиною 2k−1. Тому таблицю легко будувати, про це наступний крок.

Крок 6 · Побудова

Будуємо таблицю знизу вгору

Позначимо st[k][i] — максимум на відрізку довжиною 2k, що починається в позиції i (тобто від i до i + 2k − 1).

  • Рядок k = 0: відрізки довжиною 1, тож st[0][i] = a[i].
  • Кожен наступний рядок: блок довжиною 2k складається з двох половинок довжиною 2k−1, а їхні максимуми вже пораховано в попередньому рядку.
st[k][i] = max( st[k−1][i], st[k−1][i + 2^(k−1)] )
Крок 7 · Запит

Відповідь на запит за дві дії

Для запиту [L, R]:

len = R − L + 1 k = найбільше число, для якого 2^k ≤ len відповідь = max( st[k][L], st[k][R − 2^k + 1] )

Перший блок починається в L, другий закінчується в R (тому він починається в R − 2k + 1). Спробуйте самі на більшому масиві:

Щоб не шукати k циклом, заздалегідь рахують масив lg[len] (двійковий логарифм, округлений вниз): lg[1] = 0, lg[i] = lg[i / 2] + 1.

Крок 8 · Код

Реалізація на C++

const int MAXN = 100000, LOG = 17;
int st[LOG + 1][MAXN];   // st[k][i] = max на [i, i + 2^k - 1]
int lg[MAXN + 1];        // lg[x] = найбільше k, що 2^k <= x

void build(const vector<int>& a) {
    int n = a.size();
    lg[1] = 0;
    for (int i = 2; i <= n; i++) lg[i] = lg[i / 2] + 1;

    for (int i = 0; i < n; i++) st[0][i] = a[i];          // довжина 1
    for (int k = 1; (1 << k) <= n; k++)                   // довжина 2^k
        for (int i = 0; i + (1 << k) <= n; i++)            // блок не виходить за край
            st[k][i] = max(st[k - 1][i],                       // ліва половинка
                           st[k - 1][i + (1 << (k - 1))]);     // права половинка
}

int query(int L, int R) {                             // L і R включно
    int k = lg[R - L + 1];
    return max(st[k][L], st[k][R - (1 << k) + 1]);       // два блоки, можуть перекриватись
}

Що треба запам'ятати

Побудова
O(n log n)
Один запит
O(1)
Пам'ять
O(n log n)
  • Префіксний трюк потребує віднімання. У максимуму немає оберненої дії, тому «відрізати» початок не можна.
  • Натомість максимум не псується від перекриття: max(x, x) = x. Тому запит можна накрити двома блоками, які перекриваються.
  • Довжини-степені двійки гарантують, що два однакові блоки завжди накриють відрізок і не вийдуть за його межі, а таких довжин лише log n.
  • Так само працюють min, НСД (gcd), побітові AND і OR: для всіх них повтор елемента нічого не змінює. Для суми sparse table з двома блоками не підходить, там краще префіксні суми.
  • Масив має бути незмінним. Якщо елементи змінюються між запитами, потрібне дерево відрізків.
